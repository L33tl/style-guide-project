# Правила доступности текста (Accessibility)

Доступность (a11y) — это создание документов, которыми могут пользоваться люди с разными возможностями: с нарушениями зрения, слуха, моторики или когнитивными особенностями. Наша документация должна быть понятной и доступной каждому пользователю браузера Amigo.

## 1. Понятный язык (Plain Language)
Сложный текст — главный барьер для доступности.
*   **Пишите короткими предложениями.** Оптимальная длина — до 15–20 слов.
*   **Используйте простые слова.** Избегайте сложных терминов, если их можно заменить.
*   **Разбивайте текст на абзацы.** Одна мысль — один абзац (не более 3–4 предложений).
*   **Используйте списки.** Пошаговые инструкции должны быть нумерованными, а перечисления — маркированными.

## 2. Альтернативный текст (Alt-текст) для скриншотов
Скриншоты в документации Amigo важны, но незрячие пользователи используют программы экранного доступа (скринридеры). Они «читают» картинки через alt-текст.
*   **Каждое изображение должно иметь alt-текст.** 
*   **Описывайте смысл, а не внешний вид.** Плохо: Картинка. Хорошо: Скриншот меню Настройки с выделенной вкладкой Внешний вид.
*   **Избегайте слов «картинка», «изображение», «скриншот» в начале alt-текста.** Скринридер сам сообщит пользователю, что это картинка.
*   **Не дублируйте текст.** Если информация уже есть в тексте, alt-текст может быть кратким.

## 3. Правила оформления ссылок
Ссылки должны быть понятны вне контекста предложения.
*   **Пишите описательный текст ссылки.** 
    *   Плохо: «Чтобы узнать больше, нажмите [здесь](https://example.com)».
    *   Хорошо: «Читайте подробнее в [документации по настройкам Amigo](https://example.com)».
*   **Не используйте слово «ссылка»** в тексте самой ссылки.

## 4. Не полагайтесь только на цвет
Информация не должна передаваться только через цвет (это проблема для дальтоников).
*   Не пишите: «Нажмите на красную кнопку «Выход»».
*   Пишите: «Нажмите на кнопку «Выход» (она выделена красным цветом)».

## 5. Структура заголовков
Скринридеры и другие программы ориентируются по заголовкам для навигации по странице.
*   В документе должен быть только один заголовок первого уровня (H1, #). Обычно это название страницы.
*   Не пропускайте уровни заголовков. После H1 (заголовок первого уровня) сразу идет H2 (второй уровень, ##), затем H3 (###).
*   Не используйте жирный шрифт или заглавные буквы вместо заголовков.

## 6. Клавиатурная навигация
Хотя это относится скорее к интерфейсу, в документации стоит упоминать горячие клавиши, так как многие пользователи с ограниченными возможностями моторики не могут использовать мышь.
*   Указывайте горячие клавиши в скобках после названия действия. Пример: «Скопируйте текст (Ctrl+C)».
